Wer sendet was an wen

Jeder Pfeil zeigt in die Richtung, in die Daten fließen. Die Beschriftung nennt, was unterwegs ist.

  • →Daten fließen in Pfeilrichtung
  • ↔Daten in beide Richtungen: lesen und schreiben
  • ┄→zeitgesteuert, ohne Beteiligung eines Browsers

Alle Verbindungen

Browser → Next.js-Server
Anfrage über HTTPS. Mitglieder senden ihr Session-Cookie mit, Gäste nicht.
Next.js-Server → Browser
Antwort, vom Data Access Layer nach Rolle gefiltert: Vorschau für Gäste, alle Details für Mitglieder.
Better Auth ↔ user, session, account, verification
Konto in user anlegen, Passwort-Hash in account prüfen, Bestätigungscode in verification ablegen, Sitzung in session speichern und bei jeder Anfrage wiederfinden.
Next.js → Better Auth → Zod → Data Access Layer → ORM
Die Anfrage wandert Station für Station weiter. Scheitert eine Prüfung, endet sie dort mit einer Fehlermeldung.
ORM ↔ listings, trades
Angebote lesen und anlegen, abgeschlossene Trades speichern.
Queue → Redis → Worker
Der Job wird bei der Registrierung abgelegt und 7 Tage später an den Worker übergeben.
trades → Worker
Der Worker fragt die Anzahl der Trades des Nutzers ab.
Worker → React Email → Postfach
Nur bei 0 Trades: Die Vorlage wird zu HTML gerendert und über einen Mail-Dienst verschickt.

Die Komponenten erklärt

Was jedes Teil ist und wofür es in dieser App zuständig ist, sortiert nach Oberbegriff.

Fundament

TypeScript

Programmiersprache

JavaScript mit Typen. Der Editor erkennt viele Fehler, bevor der Code überhaupt läuft.

Aufgabe hier: Eine Sprache für Browser, Server und Worker. Zod, das ORM und Better Auth reichen ihre Typen durch den ganzen Code weiter.

Next.js

Web-Framework

Baut auf React auf und liefert Frontend und Backend in einem Projekt: Seiten, Routing und Server-Code.

Aufgabe hier: Nimmt jede Anfrage an. Server Components bauen Seiten zusammen, Server Actions und Route Handler verarbeiten Formulare und API-Aufrufe.

React

UI-Bibliothek

Setzt die Oberfläche aus wiederverwendbaren Komponenten zusammen.

Aufgabe hier: Zeigt Vorschauen, Dashboard und Handelsformulare an. React Email nutzt dieselbe Schreibweise für E-Mails.

Node.js

Laufzeitumgebung

Führt JavaScript und TypeScript außerhalb des Browsers aus.

Aufgabe hier: Darauf laufen der Next.js-Server und, als eigener Prozess, der BullMQ-Worker.

Sicherheit

Better Authaktuell

Authentifizierung

Klärt, wer anfragt. Open-Source-Bibliothek für TypeScript, die Konten und Sitzungen in der eigenen Datenbank speichert statt bei einem fremden Dienst.

Aufgabe hier: Registrierung, Login, E-Mail-Verifizierung und das Session-Cookie.
Stand: Das ältere Auth.js (früher NextAuth.js) wird seit September 2025 vom Better-Auth-Team gepflegt. Diese Seite nutzt durchgehend Better Auth.

Zod

Validierung

Beschreibt in einem Schema, wie gültige Daten aussehen, und prüft Eingaben dagegen.

Aufgabe hier: Jedes Formular und jeder API-Aufruf wird geprüft, bevor der Server damit arbeitet. Aus dem Schema entsteht zugleich der TypeScript-Typ.

Data Access Layer

Autorisierung

Kein Produkt, sondern ein Muster: eigene Server-Dateien, über die jeder Datenzugriff läuft.

Aufgabe hier: Entscheidet nach Rolle, welche Felder zurückgehen. Gäste erhalten nur previewText, Mitglieder zusätzlich memberDetails.
Merke: Mit import "server-only" kann dieser Code nicht versehentlich im Browser landen.

Daten

Prisma / Drizzle

ORM

Übersetzt TypeScript-Aufrufe in SQL und liefert typisierte Ergebnisse zurück.

Aufgabe hier: Liest und schreibt listings und trades, verwaltet Migrationen.
Wahl: Eines von beiden reicht. Prisma ist etablierter und hat ein eigenes Schema-Format, Drizzle ist schlanker und näher an SQL.

PostgreSQL

Relationale Datenbank

Speichert Daten dauerhaft in Tabellen, die über Schlüssel miteinander verknüpft sind.

Aufgabe hier: Hält die vier Better-Auth-Tabellen und die App-Tabellen listings und trades. Fremdschlüssel verbinden alles mit user. Transaktionen sorgen dafür, dass ein Trade ganz oder gar nicht gespeichert wird.

Hintergrund & E-Mail

BullMQ

Job-Queue

Warteschlange für Aufgaben, die später oder im Hintergrund laufen sollen.

Aufgabe hier: Plant bei der Registrierung den 7-Tage-Job und führt ihn im Worker aus. Fehlgeschlagene Jobs lassen sich automatisch wiederholen.
Merke: Der Worker braucht einen dauerhaft laufenden Node.js-Prozess neben dem Next.js-Server.

Redis

In-Memory-Datenbank

Sehr schneller Speicher, der Daten im Arbeitsspeicher hält.

Aufgabe hier: Bewahrt die BullMQ-Jobs auf, bis sie fällig sind. Die eigentlichen App-Daten liegen weiter in PostgreSQL.

React Email

E-Mail-Vorlagen

E-Mails als React-Komponenten schreiben, die zu HTML für Mail-Programme gerendert werden.

Aufgabe hier: Baut die Erinnerungs-E-Mail. Verschickt sie nicht selbst.

Mail-Dienst

Versand

Stellt E-Mails zu und kümmert sich darum, dass sie nicht im Spam landen.

Aufgabe hier: Nimmt die fertige E-Mail vom Worker entgegen und liefert sie ins Postfach.
Offen: Noch nicht festgelegt. Üblich sind Resend, Postmark oder Amazon SES.
